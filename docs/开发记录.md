## 2025-09-22
1. 将HugWBC和Baseline都迁移到rsl rl 3.1版本下，已经确认无法支持旧版本的rsl rl. 这出于以下两个原因
   1. `ObservationsCfg`的`critic`已经替换为了`privileged`,其不可以继承自`PolicyCfg`.
        ```python
        @configclass
            class ObservationsCfg:
            """Observation specifications for the MDP."""

            @configclass
            class PerceptionCfg(ObsGroup):
                flatten_history_dim = False

            @configclass
            class PolicyCfg(ObsGroup):
                flatten_history_dim = False

            @configclass
            class PrivilegedCfg(ObsGroup):
                flatten_history_dim = False
            # observation groups
            policy: PolicyCfg = PolicyCfg()
            privileged: PrivilegedCfg = PrivilegedCfg()
            perception: PerceptionCfg = PerceptionCfg()
        ```
   2. 对称性增强函数的定义发生了变化
   虽然仍然可以在`ObservationCfg`中接着定义`critic`，并使用`SymmetryAug.data_augmentation_tensor`进行对称性增强,但是由于我个人并没有试过,因此这里不做保证是否work
2. 将对称性损失迁移至`symmetry_aug.py`中, 同时支持[B,H*d]和[B,H,D,...]等多种尺寸的输入. \
   针对前者，调用`SymmetryAug2D`;针对后者，调用`SymmetryAug`. 需要注意的是,由于isaaclab或rsl rl的一些神奇问题,并不支持在`@configclass`的配置类中赋值函数时使用类似`SymmetryAug.data_augmentation`,这会使得`string_to_callable`时会在当前文件下寻找函数`SymmetryAug.data_augmentation`,然而实际上应该是在`SymmetryAug`模块下寻找函数`data_augmentation`. 因此这里在`rsl_rl_ppo_cfg.py`开头多套了一层.
3. `RslRlOnPolicyRunnerCfg`以及对应的`RslRlPpoEncActorCriticCfg`新增了部分参数. \
    `ObservationCfg`定义了环境返回的`TensorDict`中包含的key,而`RslRlOnPolicyRunnerCfg`则定义了如何使用这些key, 例如:
    ```python
    @configclass
    class KuavoS42RoughPPORunnerCfg(RslRlOnPolicyRunnerCfg):
        # empirical_normalization = True
        obs_groups = {
            "policy": ["policy"],
            "critic": ["policy", "privileged"],
        }
        policy = RslRlPpoActorCriticCfg(
            init_noise_std=1.0,
            actor_hidden_dims=[512, 256, 128],
            critic_hidden_dims=[512, 256, 128],
            activation="elu",
            actor_obs_normalization=True 
            critic_obs_normalization=True
        )
    
    ```
    这里新增了`obs_groups`的属性,其中key `policy`代表actor需要使用的obs,`critic`代表critic需要使用的obs,`critic`对应的输入在进行计算时会在最后一个维度进行concat. 由于isaaclab在`flatten_history_dim=True`时会神奇的将历史观测进行列优先存储,此时concat得到顺序会很怪,因此建议`flatten_history_dim=False`.
    另外, 在新版rsl rl中移除了`empirical_normalization`属性,如果需要使用经验归一化,可以在`policy`中设置`actor_obs_normalization`和`critic_obs_normalization`属性,具体参考`RslRlPpoActorCriticCfg`的文档. \
    关于新增的Attention Based Map Encoding相关的训练代码, 使用`RslRlPpoEncActorCriticCfg`进行配置.
    ```python
    @configclass
    class RslRlPpoEncActorCriticCfg(RslRlPpoActorCriticCfg):
        class_name = "EncActorCritic"
        embedding_dim:int = 64
        load_mask:int = 7+8
        # 这两个取代原有的empirical_normalization
        actor_obs_normalization=True 
        critic_obs_normalization=True
        output_attention=False  # policy是否输出attention,这里主要用于可视化
    ```
    其中`output_attention`只在play时使用,只需要关注`load_mask`即可,其含义如下: 
    ```python
    LOAD_POLICY_WEIGHTS = 1
    LOAD_CRITIC_WEIGHTS = 2
    LOAD_ENCODER_WEIGHTS = 4 
    LOAD_NORMALIZER_WEIGHTS = 8
    ```
4. 加入了attention的可视化play,具体参考`play_attention.py`即可.
   运行命令如下:
    ```bash
    python scripts/rsl_rl/play_attention.py \

    ```
    这里attention分为了10个颜色进行可视化,至于为什么是10个不是直接cmap,建议问isaaclab, 没有办法在env里面拿除了定义好的obs以为的任何数据, 也不好直接加入可视化. 为了自己可视化map_scan, 在PLAY的ObservationCfg中加入了机器人世界位姿的观测, 后续要debug什么可视化需要加入的,建议把对应的observation函数加入`vis_observation.py`中.

## 2025-09-23
1. 将`map_scan`的观测进行了修改，主要包括以下两项：
    - 原有的map scan的x和y并不和机体系严格对齐,这在sim2real和sim2sim的时候是一件很抽象的事，所以这里将其转换到了base系下，但是换句话说，这里的xy就是固定了的，有什么用呢?
    - 原有的map_scan直接view为[B,L,W,3]，这是不对的. 因为sample为xy模式,所以需要先对x方向进行遍历, 即先对L进行批处理,得到的尺寸应该是[B,W,L,3],所以修改为:`height_scan.view(B, W, L, 3).permute(0,2,1,3)`
2. 将onnx的导出从双输入修改为单输入，方便sim2real部署
